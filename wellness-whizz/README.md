# Wellness Whizz — standalone version (no Webflow, no Make.com)

The AI Supplement Advisor site, rebuilt to run on **Cloudflare** with a small backend that replaces the Webflow forms +
Make.com + Webflow CMS chain:

| Before (Webflow)                               | Now                                                     |
| ---------------------------------------------- | ------------------------------------------------------- |
| Webflow hosting                                | Cloudflare Workers + static assets (free tier is enough) |
| Webflow form → Make.com scenario → OpenAI      | `POST /api/quiz` in `src/` calls OpenAI directly         |
| Webflow CMS collections (Supplements, Results) | Cloudflare D1 (SQLite) tables in `migrations/`           |
| `/result/{sessionID}` CMS template page        | Rendered by the Worker from D1 (`src/render/result.ts`)  |
| `/supplement/{slug}` CMS template page         | Rendered by the Worker from D1 (`src/render/supplement.ts`) |
| Home page collection lists                     | Static `public/index.html` filled from D1 (`src/render/home.ts`) |

The look is unchanged: `public/` is the Webflow code export (CSS, fonts, images, `webflow.js` interactions), with links
and asset paths made local. The quiz page talks to our API instead of Webflow (`public/js/quiz.js`).

## How a quiz submission flows

1. `public/wellness-quiz.html` posts the answers as JSON to `/api/quiz` and shows the "AI is preparing" screen.
2. The Worker (`src/pipeline.ts`) asks OpenAI for 5 recommendations (Structured Outputs, see `src/openai.ts`).
3. Each recommendation is matched against the `supplements` table by normalised name. Missing ones get a full profile
   generated by OpenAI (benefits, contraindications, ratings, products, studies) and are inserted, in parallel.
4. The 5 results are stored for the session and the browser is redirected to `/result/{sessionID}`.
5. New supplements automatically appear in the home slider, the "Explore manually" list and at `/supplement/{slug}`.

If the browser loses the connection while waiting, the Worker keeps going and the result page polls until it is ready.

## Local development

```sh
cd wellness-whizz
npm install
cp .dev.vars.example .dev.vars          # DEV_FAKE_AI=true lets you test without an OpenAI key
npm run db:migrate:local                # creates the local D1 database
npm run db:seed:local                   # 8 starter supplements (optional)
npm run dev                             # http://localhost:8787
```

`npm run typecheck` runs the TypeScript compiler.

## Deploy to Cloudflare

You need a free Cloudflare account and Node.js 20+.

```sh
cd wellness-whizz
npm install
npx wrangler login

# 1. Create the database and copy the printed database_id into wrangler.jsonc
npx wrangler d1 create wellness-whizz

# 2. Create the tables and (optionally) the starter content
npm run db:migrate:remote
npm run db:seed:remote

# 3. Store the OpenAI key as a secret (never commit it)
npx wrangler secret put OPENAI_API_KEY

# 4. Deploy
npm run deploy
```

Wrangler prints the `*.workers.dev` URL. To use your own domain (for example `aiww.io`), open the Worker in the
Cloudflare dashboard → **Settings → Domains & Routes → Add → Custom domain**. The DNS records are created for you when
the domain is on Cloudflare.

### Automatic deploys from GitHub

In the Cloudflare dashboard: **Workers & Pages → Create → Import a repository**, pick this repo, set the
**root directory** to `wellness-whizz`, build command `npm install`, deploy command `npx wrangler deploy`.
Add `OPENAI_API_KEY` under the Worker's **Settings → Variables and Secrets**. Every push to the production branch then
redeploys.

## Configuration

| Setting               | Where                       | Meaning                                                               |
| --------------------- | --------------------------- | --------------------------------------------------------------------- |
| `OPENAI_API_KEY`      | secret                      | Required in production.                                               |
| `OPENAI_MODEL`        | `wrangler.jsonc` → `vars`   | Default `gpt-4.1-mini`. Any model that supports Structured Outputs.   |
| `PRODUCT_SEARCH_URL`  | `wrangler.jsonc` → `vars`   | Link template for the "View More" product buttons. `{query}` is replaced by the product name. Put your affiliate tag here. |
| `RATE_LIMIT_PER_HOUR` | `wrangler.jsonc` → `vars`   | Max quiz submissions per IP per hour (default 10). `0` disables.       |
| `DEV_FAKE_AI`         | `.dev.vars` only            | `true` returns canned data instead of calling OpenAI (no key needed). |
| Google Ads conversions| `public/js/site.js`         | Set `window.GTAG_CONVERSION_LABEL` to your `AW-…/…` label to report conversions on card clicks. |

## Bringing over your Webflow CMS content

Export the **Supplements** collection from Webflow as CSV, then:

```sh
node scripts/import-webflow-csv.mjs ~/Downloads/Supplements.csv > import.sql
npx wrangler d1 execute wellness-whizz --remote --file=import.sql
```

The script prints which CSV columns it matched to which database fields (it already knows the field names of this
site's collection: Supplement Name, Safe level, Effectiveness, Safe Option, FDA Approved, Description, Benefits,
Contraindications, Enhancing effect, Posible interactions, Why you should consider to take it?, Content, Research,
Form, Name 1-5, Link 1-5, Image 1-5). Rich-text fields are imported as HTML, option fields are mapped to the values the
templates understand, the iHerb affiliate links become the "View More" buttons, and the original slugs are kept so old
`/supplement/...` links keep working. Rows are upserted by name, so re-running the import refreshes existing rows and
overrides the starter seed.

Product images still point at Webflow's CDN. Before cancelling Webflow, run the import once with
`--download-images`: it copies them into `public/images/products/` and links the local files (commit that folder).
A bare slug such as `/supplement/zinc` redirects to the full slug (`/supplement/zinc-fe1df`).

To keep old `/result/{sessionID}` links alive, also export the **Results** collection and import it *after* the
supplements (it references them by slug):

```sh
node scripts/import-webflow-results-csv.mjs ~/Downloads/Results.csv > results.sql
npx wrangler d1 execute wellness-whizz --remote --file=results.sql
```

## Project layout

```
public/            Webflow export (static assets) + js/quiz.js, js/site.js
src/index.ts       Routes (Hono)
src/pipeline.ts    Quiz pipeline (the former Make.com scenario)
src/openai.ts      OpenAI calls, prompts and JSON schemas
src/db.ts          D1 queries
src/render/        HTML templates reusing the Webflow markup and classes
migrations/        D1 schema
seed.sql           Starter supplements (generated from scripts/seed-data.mjs)
scripts/           Seed builder and Webflow CSV importers (Supplements, Results)
```

## Costs

Cloudflare Workers, D1 and static assets have generous free tiers (100k requests/day, 5M D1 reads/day) that cover a
site of this size. OpenAI is the only paid dependency: one quiz costs roughly 6 model calls with `gpt-4.1-mini`
(1 recommendation call + up to 5 profile generations); profiles are cached in D1, so repeat supplements cost nothing.
